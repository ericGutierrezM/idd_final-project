TRADITIONAL DATA CENTERS
MareNostrum SuperComputing Center, Barcelona
Traditional Data Center - facility/space of networked 
computers and associated components(like 
telecommunications and storage) which helps business and 
organisations to function a large amount of data
Characteristics:
• Large up-front investment
• High maintenance cost (done by data center employees)
• Scaling up requires huge investments (forecasting demand 
is difficult)
• Deploying new data centers and servers takes time (slow 
provisioning)
• Owning security and compliance
• The organization’s developers are trusted for the data 
stored in data centers
• Performance is less than compared to investment
• It is easily customizable without any hard plan
• It may and may not require an internet connection
• Data Centers require experienced developers to operate 
and are considered not a viable option

--- PAGE 10 ---
12
CLOUD VS TRADITIONAL DATACENTERS
Characteristics:
• Less upfront investment
• Less maintenance cost since is the service providers 
maintain it
• Benefit from massive economies of scale  - Scaling up 
required less amount of investment and deploying new data 
centers takes minutes (stop guessing capacity)
• The service provider owns the security of the cloud, you 
own security in the cloud
• Third-Party needs to be trusted for the organization’s data 
to be stored
• Performance is huge as compared with investment
• It requires a plan to customize the cloud
• It requires a stable internet connection to provide the 
function
• Cloud is easy to operate and is considered a viable option

CLOUD DEPLOYMENT MODELS
PRIVATE CLOUD
Cloud service provided by a 
third-party provider, hardware is 
only used by a single company, 
which many times owns the 
hardware and data center
• Capital cost
• Lack of elasticity
• Potential latency
• High overhead
• High Security
• Fully customizable
PUBLIC CLOUD
Cloud service provided by a 
third-party provider, hardware 
can be shared amongst multiple 
clients
• No capital cost
• Elastic  - infinite scalability
• No latency
• Low overhead
• Faster and simpler deployments
HYBRID CLOUD
Cloud service provided as a 
combination between public and 
private cloud with automation 
and orchestration between the 
two
• Some capital cost
• Adds elasticity and flexibility
• Often used to transition to public 
cloud

• Palantir

CLOUD STORAGE – AWS S3 
22
• S3 stands for Simple Storage Service (S3)
• One of the oldest AWS services - launched in 2006 – and one of the most 
feature-rich storage platform available 
• Allows the storage and retrieval of any amount of data (up to 5T)
• It is easy to set up and easy-to-use
• Fast and cheap: quickly store and retrieve any amount of data from 
anywhere on the web at an economical storage cost
• It is secure - allows encryption
• Provides different storage classes for different use cases 
Amazon Simple Storage 
Service (Amazon S3)

CLOUD STORAGE - S3 
23
• It is object based. Think of objects just as files (i.e. Word documents, 
movies, pictures, CSVs, parquet files).
• Objects consist of the following:
• Key – name of the object
• Value – data
• Version
• Metadata – data about data
• Sub-resources (access control lists, bucket policies)
• Files are stored in buckets. A bucket is a folder where you put your files.
Amazon Simple Storage 
Service (Amazon S3)

• Serverless architecture is an approach to software design that allows developers 
to build and run services without having to manage the underlying infrastructure. 
Fundamental serverless terms :
• Invocation - Single function execution
• Duration - Time taken for a lambda function to execute
• Cold Start - Latency when a function is triggered for the first time / after an inactivity  
period
• Concurrency Limit - The number of function instances that can run simultaneously 
in one region
• Timeout - The amount of time that a cloud provider allows a function to run before 
terminating it – 15mins
Use Cases:
• Trigger-based tasks
• Building RESTful APIs
• Asynchronous processing
• Security checks
• Continuous Integration (CI) and Continuous Delivery (CD)

import json
import boto3
import datetime
import pandas as pd
from io import StringIO
def lambda_handler(event, context):
s3 = boto3.client('s3')
# Replace with your actual bucket name
bucket_name= 'student1-bucket-idd'
input_key = 'input.csv'
try:
# Read CSV from S3
response = s3.get_object(Bucket=bucket_name, Key=input_key)
content = response['Body'].read().decode('utf-8')
df = pd.read_csv(StringIO(content))
# Do any transformation here (this is just a placeholder)
df_processed= df.copy()
# Prepare to write back to S3
timestamp = datetime.datetime.utcnow().isoformat()
output_key = f"processed/output_{timestamp}.csv"
csv_buffer = StringIO()
df_processed.to_csv(csv_buffer, index=False)
# Upload to S3
s3.put_object(
Bucket=bucket_name,
Key=output_key,
Body=csv_buffer.getvalue().encode('utf-8')
)
return {
"statusCode": 200,
"body": json.dumps({
"message": "CSV processed and saved to S3",
"bucket": bucket_name,
"output_key": output_key
})
}
except Exception as e:
return {
"statusCode": 500,
"body": json.dumps({
"error": str(e)
})
}
